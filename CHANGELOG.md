# Changelog

The first version, 2.5.0, matches the `@agents-forge/aiqa` release the agents' prompts were ported from. This
repository is kept separate from the npm package: changes are made here, and listed below.

## 2.5.0 — 2026-11-11

The repository becomes the AIQA agents bundle. The earlier proof of concept (Playwright's planner, generator and
healer agents, the saucedemo tests and the deck) is removed; it stays in git history.

### Added
- **Eight agents for Claude Code** (`.claude/agents/`), ported from @agents-forge/aiqa 2.5 (aaff193):
  - the full suite: `analyst`, `qa-planner`, `qa-engineer`, `qa-reviewer`, `qa-reporter`;
  - the story workflow: `story-designer`, `story-explorer`, `story-automator`.
- **Four skills:**
  - `qa-pipeline`: step by step or `--auto`, with the reviewer deferred. A step name runs just that step of the last
    run. The skill saves the reporter's report, because Claude Code doesn't let a subagent write `summary_report.md`;
  - `qa-story`: Design → Explore → Automate → Run, with code for the story hash, the story Playwright config and
    writing results into the test cases;
  - `qa-setup`;
  - `qa-dashboard`: live, or a `--static` snapshot.
- **A model for each agent:**
  - the dashboard's Models page saves the picks to `.aiqa/ai.json` (the npm package's file and format);
  - `qa-pipeline` and `qa-story` start each agent with its role's model;
  - `--model` and `--model-<role>` set them for one run.
- **An example:** `examples/saucedemo`, a walkthrough of a real run with screenshots.
- **A Claude Code plugin and marketplace:** `/plugin marketplace add rohan12patil/AIQA`, then
  `/plugin install aiqa@agents-forge`.
- **GitHub Copilot copies** in `.github/agents/` and `.github/skills/`, generated by `scripts/build.mjs`.
- **Tests and CI.** The tests check parity with the npm package: story hash, file names, step state, the results
  writer, the story config.

### Changed from @agents-forge/aiqa 2.5
Found in the first full run on saucedemo (see `examples/saucedemo`):
- **The saved login no longer applies to every test.** The qa-engineer's `playwright.config.ts` no longer loads
  `.aiqa/auth-state.json`. Tests start signed out, and tests that need a signed-in user use a sign-in fixture.
- **Listing tests keeps the latest results.** The generated config uses the plain list reporter for `--list`, so
  a listing no longer overwrites the JSON, JUnit and HTML reports. The qa-reporter and story-automator prompts give
  the safe command, `npx playwright test --list --reporter=list`.
- **Story runs use the suite's test-id attribute.** When the project's `playwright.config.ts` sets
  `testIdAttribute` (e.g. `data-test`), the story config sets it too, so the shared page objects work in story runs.
  Without it, the story config is the npm package's, unchanged.
