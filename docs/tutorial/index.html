Tutorial · about 15 minutes to read

From a URL to a tested Playwright suite

Agentic QA is an open-source team of QA agents for Claude Code and GitHub Copilot. You give them your web app's address, in chat. They explore it, plan the testing, write the tests, check them and run them. This page walks you through it, step by step.

Quick start, in Claude Code 
/plugin marketplace add qa-crew/agentic-qa
/plugin install agentic-qa@qa-crew
/agentic-qa:qa-setup
/agentic-qa:qa-pipeline https://www.saucedemo.com
/agentic-qa:qa-dashboard
  • Requirements
  • Risk-based test plan
  • Test cases
  • Playwright page objects & specs
  • A review of every selector
  • An executive test report

1What you get

Eight agents, each with one job, and four commands that run them for you.

The full suite: five agents, one after another

  1. 1 · analystExploreWalks every page, saves a snapshot of each, writes the requirements25 min
  2. 2 · qa-plannerPlanA test plan ranked by risk11 min
  3. 3 · qa-engineerAutomateTest cases, page objects, fixtures and specs51 min
  4. 4 · qa-reviewerReviewChecks every selector against the snapshots19 min
  5. 5 · qa-reporterReportRuns the tests and writes the report5–8 min

Times are from real runs on saucedemo.com with Claude Opus 5.5. Your app and model will change them.

One user story at a time

  1. codePullFinds the story file
  2. story-designerDesignTestable criteria and manual test cases
  3. story-explorerExploreTries every case in the real app
  4. story-automatorAutomatePlaywright tests for the verified cases
  5. codeRunRuns them and writes the results into the cases

The four commands

CommandWhat it does
/agentic-qa:qa-setupChecks and installs what the agents need. It asks before installing anything.
/agentic-qa:qa-pipeline <url>Runs the five full-suite agents in order.
/agentic-qa:qa-story <KEY>Runs one story: Design, Explore, Automate, Run.
/agentic-qa:qa-dashboardOpens a live page that shows progress, files and results.
i

The agentic-qa: prefix appears when you install Agentic QA as a Claude Code plugin. If you copy the files, or use GitHub Copilot, the commands have no prefix: /qa-pipeline, /qa-story and so on.

2Before you start

You need three things. Setup (step 4) installs the rest.

  • Claude Code (the terminal, the desktop app or the IDE extension), or GitHub Copilot in VS Code.
  • Node.js 20 or newer. Check with node --version.
  • A project folder for the tests, and the address of the app you want to test. It can be a local address, such as http://localhost:3000.
✓

Want to try it first? Use https://www.saucedemo.com, a public demo shop. Every example on this page comes from a real run on it.

3Install

Pick the way that fits you. You only do this once.

In Claude Code, type:

/plugin marketplace add qa-crew/agentic-qa
/plugin install agentic-qa@qa-crew

Or from a terminal, in one step:

claude plugin install agentic-qa --marketplace qa-crew/agentic-qa

Restart Claude Code. The commands are now /agentic-qa:qa-pipeline and so on, and the agents are agentic-qa:analyst and so on.

To update later: claude plugin marketplace update qa-crew, then claude plugin update agentic-qa@qa-crew, and restart. To get updates automatically, open /plugin, go to Marketplaces, pick qa-crew and turn on auto-update. It's off by default.

Just trying it? claude --plugin-dir <path to a clone> loads the plugin for one session, without installing it.

Once, for the whole team: commit this to .claude/settings.json in your team's repository.

.claude/settings.json 
{
  "extraKnownMarketplaces": {
    "qa-crew": { "source": { "source": "github", "repo": "qa-crew/agentic-qa" } }
  },
  "enabledPlugins": { "agentic-qa@qa-crew": true }
}

Or let Claude Code write it for you:

claude plugin marketplace add qa-crew/agentic-qa --scope project
claude plugin install agentic-qa@qa-crew --scope project

Then each teammate, once per clone: the file tells Claude Code where the plugin comes from and turns it on, but it doesn't install it. Open the project, say yes when Claude Code asks to trust the folder, and run:

claude plugin install agentic-qa@qa-crew --scope project

Copy .claude/agents/ and .claude/skills/ from this repository into your project's .claude/ folder. Or copy them into ~/.claude/ to have them in every project.

  • The commands have no prefix: /qa-pipeline, /qa-story, /qa-setup, /qa-dashboard.
  • Copy all four skill folders. The dashboard uses scripts from qa-story.

Copy .github/agents/ and .github/skills/ from this repository into your repository's .github/ folder.

  • The eight agents appear in Copilot's agent picker.
  • The commands are /qa-pipeline, /qa-story, /qa-setup and /qa-dashboard.
  • The instructions are the same as Claude Code's, with Copilot's tool names.

4Set up your project

Open Claude Code (or Copilot Chat) in your project folder and run setup once.

/agentic-qa:qa-setup

It checks each item, shows a short table, and asks before installing what's missing:

ItemWhyNeeded?
Node.js 20+Runs everythingYes
A package.jsonHolds the test dependenciesYes
@playwright/testRuns the testsYes
playwright-cliLets the agents drive a browserYes
ChromiumThe browser the tests run inYes
@axe-core/playwrightAccessibility testsOptional
k6Load testsOptional

It also offers two things you should say yes to:

Permission rules

The agents run playwright-cli many times. These rules stop Claude Code asking you each time.

.gitignore lines

Keep your saved login, reports and screenshots out of git. The requirements, plan, cases and tests are meant to be committed.

What it adds to .gitignore 
.aiqa/auth-state.json
.aiqa/reports/
.aiqa/evidence/
.aiqa/progress.jsonl
!

.aiqa/auth-state.json holds a signed-in browser session. Never commit it.

5Work with Claude or Copilot

You don't run Agentic QA like a program. You talk to it, in the same chat you already use for code.

What happens when you type a command

You

Type a command, read each result, answer the questions, ask for changes.

⇄chat

Your chat session: the lead

Checks the tools, hands each step to the right agent, checks the files it wrote, shows you the result and asks before going on.

→one step each

The agents

Each does one job in its own workspace, writes its files, and never stops to ask you.

analystqa-plannerqa-engineerqa-reviewerqa-reporter

Everything the agents make is a plain file under .aiqa/. You, the lead and the dashboard all read the same files, so nothing is hidden in the chat.

Ask in plain words

Between steps, or after a run, talk to the lead like a colleague. It can read every file the agents wrote. For example:

  • "Why did TC-CART-N-002 fail? Show me the snapshot it used."Reads the results and the snapshots, and explains.
  • "The reviewer flagged a networkidle wait. Fix it."Edits the spec; then you re-run the tests.
  • "Add test cases for the promo-code field to the checkout module."Extends the test cases and the spec.
  • "Run the regression tests, then summarise what failed."Same as /agentic-qa:qa-pipeline qa-reporter --grep @regression.

You can also call one agent directly, for example: "Use the agentic-qa:qa-reviewer agent to review the generated suite."

Claude Code or Copilot

  1. Open Claude Code in your project folder: the terminal (claude), the desktop app or the IDE extension.
  2. Type /agentic-qa:qa-pipeline <your url>. Type /agentic-qa to see all four commands.
  3. Each step runs as its own agent, so your chat stays short and readable while the agents work.
  4. Pick each agent's model on the dashboard, or with --model options (step 9).
  1. Open Copilot Chat in VS Code, in your repository with the copied .github/agents/ and .github/skills/.
  2. Type /qa-pipeline <your url>, or pick an Agentic QA agent, such as analyst, in the agent picker and ask it directly.
  3. Where Copilot can't hand a step to another agent, the command tells Copilot to follow that agent's instructions itself.
  4. Copilot uses its own model picker, so the dashboard's model choices don't apply.

6Run the full suite

One command takes you from an address to a reviewed, running test suite.

  1. Start the pipeline 
    /agentic-qa:qa-pipeline https://www.saucedemo.com
    It checks that the tools are installed, shows which model each agent will use, and starts the analyst.
  2. Read each step's output, then continue By default it pauses after each step and shows you what was written. Answer Continue to go on, or Stop to look closer first.
  3. Read the report The last step writes .aiqa/reports/summary_report.md, with a clear status line. For details, open the Playwright report: 
    npx playwright show-report .aiqa/reports/playwright-report
  4. Run the review when you have time The reviewer is the slow step, so step-by-step runs leave it for later: 
    /agentic-qa:qa-pipeline qa-reviewer

Run it without pauses

Add --auto to run all five steps in one go, the reviewer included:

/agentic-qa:qa-pipeline https://www.saucedemo.com --auto

Options

OptionWhat it does
--grep <tags>Which tests the reporter runs: @smoke (the default, fast), @regression, "@smoke|@accessibility", or all
--autoNo pauses between steps
--skip a,bLeave steps out, e.g. --skip qa-reviewer
--requirements <file>An existing requirements document for the analyst to merge with what it finds
--headedShow the browser while the analyst explores
--users N --minutes MSize of the load test, with @performance (10 users for 2 minutes by default)
--model, --model-<role>The model for every agent, or for one, this run (see step 9)
i

Accessibility and load tests are opt-in. They're written only when --grep includes @accessibility or @performance, and when @axe-core/playwright or k6 is installed.

Run one step again

Give a step name instead of the address. It runs just that step, as part of the last run:

/agentic-qa:qa-pipeline qa-reporter --grep @regression

What it writes

Everything goes under .aiqa/, except playwright.config.ts at the root. If you already have one, it asks before replacing it.

.aiqa/ ├── snapshots/*.yml one accessibility snapshot per page or state ├── requirements/requirements.md ├── test-plan/test_plan.md ├── test-cases/<module>.md ├── test-scripts/ <module>.spec.ts, pages/<module>.page.ts, fixtures.ts ├── reports/ review_report.md, summary_report.md, test-results/, playwright-report/ └── progress.jsonl step progress, for the dashboard playwright.config.ts

On saucedemo, that came to 56 snapshots, 22 test-case files with 192 cases, 20 page objects and 20 specs with 197 tests. The example shows excerpts from each step.

7Test one user story

Working on a single feature? Give Agentic QA the story, and it designs, checks and automates its tests.

  1. Write the story Save it as .aiqa/stories/<KEY>-<name>.md. Or paste the story text in chat and ask the lead to save it. It can also read the story from Jira, Rally or Octane if one is connected.
    .aiqa/stories/SD-1-login.md 
    ---
key: SD-1
title: Login with the demo accounts
---
# SD-1 — Login with the demo accounts

## Description
As a shopper I want to sign in so I can buy things.

## Acceptance Criteria
- A standard user reaches the products page
- A locked-out user sees "Sorry, this user has been locked out."
  2. Run it 
    /agentic-qa:qa-story SD-1 --url https://www.saucedemo.com
    Add --url the first time, or save the address as appUrl in .aiqa/workspace.json.
  3. Review the test cases when it pauses It stops after Design and after Explore. Open .aiqa/test-cases/SD-1-login.md, then edit, add or delete cases before you continue. Add --auto to skip the pauses.
  4. Read the results in the same file The Run step fills in Last Result and Evidence (a screenshot) for every case, and adds a row to Run History.

The defect rule

When the app contradicts the story, Explore never changes the expected result to match the app. It marks the case Possible defect, and Automate writes it as test.fixme.

Results come from code

Pass and fail are read from Playwright's own results, never written by an agent. So a result is never made up.

On saucedemo, SD-1 produced 2 testable criteria, 9 open questions and 12 test cases. All 12 were verified in the app and passed, in about 13 minutes.

More options: --step design|explore|automate|run runs one step, and --force redoes a step that's already done.

8The dashboard

A small local page that follows a run as it happens and shows everything the agents wrote.

/agentic-qa:qa-dashboard

It gives you a link like http://127.0.0.1:52341/3f9c…/. The page refreshes every two seconds. The left rail has four views: Full suite, Stories, Results and Models. Select any image to see it full size.

Themes, dark mode and phones

Use the menu at the top right to pick a theme, Slate or Industrial, and light, dark or your system's setting. The page also works at phone width.

  • Private: it serves on your computer only (127.0.0.1), behind a random link.
  • Read-only: it only reads .aiqa/. The one exception is the Models page, which saves your choices.
  • Shareable: /agentic-qa:qa-dashboard --static saves one self-contained file, .aiqa/reports/dashboard.html, that you can attach or send.

9Choose the models

Each agent can run on its own Claude model, so you can spend where it matters.

On the dashboard: open Models, pick Session model, Sonnet, Opus, Haiku or Fable for Default and for each role, then press Save.

For one run:

/agentic-qa:qa-pipeline https://my-app.com --model-qa-planner opus --model-qa-reporter sonnet

When several choices apply, the first one in this list wins:

  1. an option on the command;
  2. the role's own pick on the Models page;
  3. the Default pick;
  4. the model of your Claude Code session.

The picks are saved in .aiqa/ai.json. A change applies from the next step that starts. In Copilot, use Copilot's own model picker.

10Tips from a real run

What we learned running everything on saucedemo.com.

✓

Plan for time and usage. The full suite took about 1 hour 52 minutes of agent time with Opus on every role. On a Claude Pro plan, that needed more than one 5-hour usage window. Use a lighter model for some roles, or run the steps one at a time.

✓

Start with smoke tests. The default @smoke run takes about half a minute. Run --grep @regression or --grep all once you trust the suite.

✓

Review before you commit. The agents never run git commands that change your repository. You review what they wrote, and you commit it.

Running without anyone watching

You can run a command headless with claude -p. With nobody there to answer, Claude Code needs permission for everything the agents do up front. Put the rules in .claude/settings.local.json:

.claude/settings.local.json 
{
  "permissions": {
    "allow": [
      "Bash(playwright-cli:*)", "Bash(npx:*)", "Bash(node:*)", "Bash(mkdir:*)",
      "Bash(find:*)", "Bash(ls:*)", "Bash(cat:*)", "Bash(npm ls:*)",
      "Read", "Write", "Edit", "Glob", "Grep", "Agent"
    ]
  }
}
claude -p "/agentic-qa:qa-pipeline https://my-app.com --auto" --permission-mode acceptEdits
!

Use the settings file, not --allowedTools. The command line splits a rule at its spaces, so Bash(npm ls:*) is lost.

11When something goes wrong

A run stopped halfway (usage limit, closed terminal)

Nothing is lost: each finished step's files stay on disk.

  • Full suite: run the steps that are left by name, e.g. /agentic-qa:qa-pipeline qa-engineer, then qa-reviewer, then qa-reporter. They join the last run, so the dashboard still shows one run.
  • Story: run the same /agentic-qa:qa-story command again. It continues from the first step that isn't done.
"playwright-cli: command not found"

Run /agentic-qa:qa-setup, or install it yourself with npm install -g @playwright/cli@latest. Without it, the agents can't open the app.

The tests fail because Chrome isn't installed

The generated playwright.config.ts uses channel: "chrome", the Chrome already on your computer. If you don't have Chrome, delete that option, and Playwright uses its own Chromium.

I already have a playwright.config.ts

The pipeline asks once whether to replace it or keep it. If you keep yours, add .aiqa/test-scripts to its testDir, so the reporter can find the new tests.

Claude Code asks permission for every browser command

Say yes to the permission rules that /agentic-qa:qa-setup offers. It adds them to .claude/settings.json and keeps your other settings.

Only the smoke tests ran

That's the default, for fast feedback. Run the rest with /agentic-qa:qa-pipeline qa-reporter --grep @regression, or --grep all for everything. Firefox, WebKit and mobile are commented out in playwright.config.ts; uncomment them to include them.
